## Java design, step by step

1. `State` mirrors the C structure: `pc`, `mem[65536]`, `reg[8]`, and `numMemory`. Java initializes every integer to zero, including unused memory. Instruction count is a separate `long` in the execution loop.
2. `loadMachineCode` reads one signed decimal integer per physical line, stores it at the next address, echoes `memory[address]=word`, and increments `numMemory`. It rejects malformed words, 32-bit overflow, and a 65,537th word.
3. `simulate` prints the current state, calls `executeOne`, and counts the executed instruction. On halt it prints the three required summary lines and exactly one final state, then returns.
4. `executeOne` fetches from the old PC, decodes the opcode and register fields, applies the instruction, and commits the computed next PC once. Sequential execution, including halt, advances PC by one.
5. `checkedAddress` validates fetch, load, and store addresses against the entire memory array. Load/store address addition uses `long` for diagnostics so invalid sums cannot wrap into a valid array index. Register arithmetic remains Java `int` with 32-bit wraparound.
6. `printState` ports the C strings literally. `println` provides native line endings, matching Windows C text output. It starts with a blank line and `@@@`, prints only the `numMemory` loaded words and all eight registers, and ends with `end state` and a newline.
7. `main` checks the single input argument, opens UTF-8 input with automatic resource cleanup, loads, and runs. Success returns exit 0. Usage, input, and checked runtime errors print to stderr and exit 1; they never print false halt statistics.

The instruction implementation is:

| Opcode | Operation | Next PC |
| --- | --- | --- |
| 0 add | `reg[dest] = reg[A] + reg[B]` | old PC + 1 |
| 1 nand | `reg[dest] = ~(reg[A] & reg[B])` | old PC + 1 |
| 2 lw | `reg[B] = mem[reg[A] + offset]` | old PC + 1 |
| 3 sw | `mem[reg[A] + offset] = reg[B]` | old PC + 1 |
| 4 beq | Compare registers | old PC + 1 + offset if equal; otherwise old PC + 1 |
| 5 jalr | Store old PC + 1 in B | Original A when A differs from B; newly written return address when identical |
| 6 halt | Stop after counting this instruction | old PC + 1 |
| 7 noop | No register or memory change | old PC + 1 |

Decode uses `(word >>> 22) & 7`, `(word >>> 19) & 7`, `(word >>> 16) & 7`, and `word & 7` for opcode, A, B, and R-type destination. `(int) (short) (word & 0xFFFF)` sign-extends the offset: `0xFFFD` becomes -3. A taken branch at PC 4 with offset -3 therefore targets PC 2.

`jalr` preserves the original target before writing the return register. If source and destination are the same register, the target becomes the newly written return address, so execution falls through. Register zero is never forcibly reset.

Execution loop pseudocode:

```text
executed = 0
repeat:
    printState(state)
    halted = executeOne(state)
    executed++
    if halted:
        print halt message, executed count, final-state label
        printState(state)
        return executed
```

## Documented behavior where the fragment is incomplete

These are implementation assumptions, not additional confirmed instructor requirements:

- Machine-code files are UTF-8; LF and CRLF are accepted; the final newline is optional.
- A whole decimal token is required, with optional sign and surrounding whitespace. Blank lines, comments, hexadecimal, and numeric prefixes such as `12junk` are rejected. This is stricter than the fragment's `sscanf("%d", ...)` prefix acceptance.
- File length is capped at physical memory capacity. The C loader does not protect its array against excess input.
- Invalid fetch/load/store addresses cause a checked error. The C fragment does not specify behavior for out-of-bounds memory access.
- Fetch and data access can use zero-initialized memory beyond the loaded range. `sw` preserves `numMemory`; state printing continues to show only the initially loaded range.
- An empty file loads zero words. Production execution requires a halt instruction to terminate; there is no artificial instruction limit or implicit halt at the end of loaded input.
- The decoder reads the defined fields and ignores unused bits. All three-bit opcode values denote one of the eight instructions.

A halt at memory address 65,535 advances the final PC to 65,536 without attempting another fetch. A branch or jump outside memory is diagnosed on the following fetch. Error traces may contain the pre-instruction state of the failed attempt.
